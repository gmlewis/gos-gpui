W3 — the event queue is scoped per window.
Tier: `gos run --main-thread`, and every other tier.

BEFORE THE WORK. Command, against a pristine copy of this project at HEAD
(`git archive HEAD` into /tmp/gpui-before):

    cd /tmp/gpui-before
    timeout -k 5 30 gos run --main-thread tests/gui/w3_events.gos

Output (exit 0 — the probe quits itself on the first failure):

  FAIL W3 the child window drained 1 event(s) raised by another window
  FAIL W3 the first window drained 3 event(s) raised by another window, at frame 3
  FAIL W3 the child window drained 1 event(s) raised by another window

This is the leak itself, not a missing name: the probe deliberately uses no
binding function that did not already exist, so this transcript is the
behaviour. The child's first render drains the parent's event; the parent's
third frame drains the child's three.

A minimal reproduction of the same thing, run on the same tree, makes the shape
plainest:

    use gpui
    ...
        gpui::open_window("diag3 child", .., || {
            let cf = gpui::frame()
            println(f"CHILD frame {cf} drained={gpui::take_events().len()}")
            ...

     parent frame 1
     CHILD frame 2 drained=1
     parent frame 3
     CHILD frame 4 drained=1
     parent frame 5
     CHILD frame 6 drained=1
     CHILD frame 7 drained=0
     parent frame 8
     parent quitting at 8

The child drains one event on its first three renders. Only the parent raises
any, so every one of those is the parent's. `store.rs` held one
`LazyLock<Mutex<VecDeque<String>>>` for the process, and whichever window
repainted first took whatever was in it.
