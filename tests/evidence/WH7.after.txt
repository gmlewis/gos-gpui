The loud half, which is the half the row asks for and which no other check here can
see — a program opened with a bad key says so on stderr, once per distinct spec:

    $ gos run --main-thread <a program opened with "minsize=420 nosuchkey=1">
    OK ...
    gpui: unknown window options: minsize=420 nosuchkey=1

What is new: `gpui-binding/src/options.rs` (new) is one parse of the vocabulary, with
every key it has in a single `match` and everything else collected into
`Options::unknown` in token order. `app.rs::run_app`'s own four-key parser is gone, so
the first window and every window after it cannot disagree again — which they did:
`background=transparent` was honoured by one parser and ignored by the other, and
`place=center` was read into `centered` and then compared in an `if` whose two arms
were the same expression. `gpui::unknown_window_tokens(spec)` is the reader, the
counterpart of `gpui::unknown_style_tokens`.

The two vocabularies are deliberately separate lists, and the headless test says so:
`minsize=` is unknown to the *style* language and `p=16` is unknown to the option
language, so a token in the wrong string is reported either way.
