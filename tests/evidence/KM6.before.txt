KM6 — Shift-Tab, key-up and modifier fidelity.

BEFORE THE WORK.

Two transcripts, because this row's probe cannot produce one on its own. The
first is the failure the probe as written meets; the second is the behavioural
red for the defect the row actually names, taken by substituting out the *one*
call the binding was missing at HEAD and changing nothing else.

**1. The probe as written, against HEAD's binding.**

`gpui::send_key_up` — the release half of the row — does not exist at HEAD, and
the toolchain's failure mode for an unbound binding function is not a diagnostic:

    $ env -u GOSSAMER_IN_RUNNER gos check tests/gui/km6_modifiers.gos
    check: ok (2 items typed)

    $ timeout -k 5 40 gos run --main-thread tests/gui/km6_modifiers.gos
    exit 124, no output

The checker passes the probe and the run then produces nothing at all, because
the callback is abandoned at the unbound name above the `gpui::animate()` that
would ask for the next frame, so the window idles. That is the weak kind of red —
an unresolved symbol, and one the checker does not even report — and it is
recorded as weak rather than dressed up.

**2. The behavioural red, for the defect the row names.**

The probe was copied inside the project with `gpui::send_key_up("a")` replaced by
a `set_text` call and nothing else changed, so the key-down half runs against
unmodified HEAD code:

    $ timeout -k 5 40 gos run --main-thread tests/gui/zz_scratch_km6.gos
    FAIL KM6 the first keystroke reached the program as "tab", not "shift-tab":
    Shift-Tab is indistinguishable from Tab

That is the row's own sentence, measured: `gpui::on_keys(true)` reported
`event.keystroke.key`, and gpui maps **both** Tab and Shift-Tab to the key
`"tab"` (`gpui-0.2.2/src/platform/keystroke.rs:18-31`, and `unparse` at `:741`
spells the modifier half that `key` drops). The modifier state arrived nowhere:
`a` and `A`, `c` and `cmd-c`, `tab` and `shift-tab` were all the same event.

**3. What the row's key-up clause turned out to be.**

The release is *observable* — gpui delivers `PlatformInput::KeyUp` to any
`capture_key_up` listener on the dispatch path, and the binding now registers one
on the window root — but it cannot be **synthesized**, so no probe can drive it:

    $ grep -n "pub fn dispatch_keystroke" -A 2 ~/.cargo/registry/src/*/gpui-0.2.2/src/window.rs
    3540:    pub fn dispatch_keystroke(&mut self, keystroke: Keystroke, cx: &mut App) -> bool {
    ...  PlatformInput::KeyDown(KeyDownEvent { .. })

    $ grep -n "struct DispatchEventResult" ~/.cargo/registry/src/*/gpui-0.2.2/src/window.rs
    1273:pub(crate) struct DispatchEventResult {

    $ grep -n "pub fn dispatch_event" ~/.cargo/registry/src/*/gpui-0.2.2/src/window.rs
    3581:    pub fn dispatch_event(&mut self, event: PlatformInput, cx: &mut App) -> DispatchEventResult {

`dispatch_keystroke` is the key-*down* path; `dispatch_event` is the only public
entry that takes a `PlatformInput` and it returns a `pub(crate)` type, so calling
it from this crate does not compile — the error is in `KM6.after.txt`. That is a
limit on the *check*, not on the capability, and it is recorded as such.
