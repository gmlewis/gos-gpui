Round 99 — `09_input`'s five deviation bullets, and the two that were wrong.

At HEAD, `examples/09_input.gos` carried this block:

    // Deviations:
    //   * the widget is not Gossamer code — see above and PORTING.md;
    //   * upstream binds thirteen actions through the application keymap
    //     (`cx.bind_keys` / `on_action`); the binding owns the one keymap, so the
    //     editor matches keystrokes itself. Same keys, different plumbing;
    //   * upstream focuses the input at startup; here the editor takes focus the
    //     once, when it is created, since a binding function has no `Window` to
    //     focus it with afterwards — clicking, tabbing away and returning all
    //     behave normally from then on;
    //   * upstream's shell is `InputExample` — a header, this log and a Reset
    //     button. That shell is reproduced here, with the log fed by
    //     `gpui::observe_keystrokes`, which sees every keystroke whether or not the
    //     editor handled it, exactly as upstream's `cx.observe_keystrokes` does;
    //   * Reset clears the text and the log; upstream's handler clears the text.

Two things in it were wrong, and they were wrong in opposite directions.

--------------------------------------------------------------------------------
1. The last bullet was false — there was no deviation to describe
--------------------------------------------------------------------------------
Upstream's Reset handler, `tools/upstream/examples/input.rs:621-627`:

    impl InputExample {
        fn on_reset_click(&mut self, _: &MouseUpEvent, _window: &mut Window, cx: &mut Context<Self>) {
            self.recent_keystrokes.clear();
            self.text_input
                .update(cx, |text_input, _cx| text_input.reset());
            cx.notify();
        }
    }

`recent_keystrokes.clear()` on :623 is the keystroke log, and `text_input.reset()`
(`:250-258`) empties the content and drops the selection. So upstream's Reset clears
**both** — exactly what the port does:

    } else if id == "reset" {
        gpui::set_text("input", "")
        gpui::list_clear("keys")
    }

The bullet's second clause, "upstream's handler clears the text", is false, and with it
gone there is no difference left to state. The bullet is deleted, and the fact it got
wrong is written into the shell bullet instead, where a reader comparing the two
windows will want it — with the citation, so the next round does not have to re-derive
it.

--------------------------------------------------------------------------------
2. The keymap bullet was true and incomplete — it hid the pair's largest difference
--------------------------------------------------------------------------------
"Same keys, different plumbing" is right about the *plumbing*: upstream binds thirteen
strokes through the application keymap (`cx.bind_keys` / `on_action`,
`input.rs:680-694`) and the binding owns the one keymap, so the editor matches those
thirteen on the element itself. All thirteen leave the same text either way.

It is not right about the key *set*. The binding's editor is a document editor and
handles more strokes than upstream binds anything for — `enter`, `up`, `down`,
`pageup`, `pagedown`, their shift-extended twins and `cmd-left`/`cmd-right` — and that
is not a mechanism difference with the same pixels: press `enter` in the two windows
and upstream's text is unchanged while the port's gains a break. Upstream's text can
never hold one at all: `enter` reaches nothing, and the only path that could put a break
there is a paste, which strips them (`input.rs:133`, `text.replace("\n", " ")`).

**This is round 97's class of hole, in a second file.** The census was green at 83 with
a row for this bullet, classified `visible`, and the note it carried — "keystrokes are
matched by the editor, not by the application keymap" — describes the *invisible* half.
The visible half had no bullet and no row, and `scripts/pair-census.sh` cannot see that:
it checks that every bullet has a row, not that every difference has a bullet.

The plumbing row is therefore reclassified **`invisible`** (the thirteen behave
identically; only the mechanism differs) and the visible half gets its own bullet, its
own row, and a class of **`forced`** — not chosen but constrained: `ui::editor(key,
placeholder, style)` hands out the binding's editor whole, with no way for a program to
narrow its key set, and register row `DW1` is that editor's own check, so the extra keys
cannot be dropped without failing a row that is already terminal.

--------------------------------------------------------------------------------
