**A behavioural red**, and the only one in this block — the failing assertion is the
probe's first, and it calls nothing round 17 added. The other WH rows could only show
an unresolved name and a timeout, because the reader *was* the capability; here the
capability is a placement, and a placement is observable with functions that already
existed.

Why the first attempts at this transcript were `exit 124` and silence, and why it was
not the program: they were the **stale build lock** (see "The stale build lock"). The
recipe above clears locks with this repo's `scripts/unlock-stale-build.sh`, which does not
exist in the `git archive HEAD` copy — that copy's `scripts/` holds only `update-api` —
so the pristine tree's runs were polling a lock for five minutes and the `timeout` killed
them before the probe painted a single frame. With the lock cleared by the `find`/`rm`
loop the same run prints its failure on the first try, and the pty is not needed:

    $ for f in $(find ~/.cache/gossamer -name ".gos-build.lock"); do
        pid=$(tr -d '[:space:]' < "$f"); ps -p "$pid" >/dev/null || rm -f "$f"; done
    $ timeout -k 5 25 gos run --main-thread tests/gui/wh4_display_place.gos
    FAIL WH4 the child opened with place=center at x=7, where the display's centre
    puts a 300 wide window at 1130; it was given x=7
    exit=0

This file previously claimed the silence was stdout buffering. It was not: that was a
guess written down before it was tested, and the same mistake has now been made three
times in this run — a silent `exit 124` in this project is a lock until it is proven
otherwise. The correction stands here rather than in a footnote.

The bug, quoted from the `git archive HEAD` copy at
`gpui-binding/src/app.rs:466-476`:

    window_bounds: Some(if centered {
        WindowBounds::Windowed(Bounds::new(
            gpui::point(px(x as f32), px(y as f32)),
            size(px(w as f32), px(h as f32)),
        ))
    } else {
        WindowBounds::Windowed(Bounds::new(
            gpui::point(px(x as f32), px(y as f32)),
            size(px(w as f32), px(h as f32)),
        ))
    }),

`centered` was set by `place=center` and then compared in an `if` whose two arms were
the same expression, so the token did nothing at all for a window opened with
`gpui::open_window`. `display=` did not exist: it was not a key of either parser, and
no window was ever told which display to open on.
