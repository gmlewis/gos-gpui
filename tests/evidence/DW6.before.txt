DW6 — queued prompts.

BEFORE THE WORK.

**The row's obstacle had a line number, and it says what the queue is for.** `Window::prompt`
(`gpui-0.2.2/src/window.rs:4141`) hands back a `oneshot::Receiver<usize>` carrying the index of the
button clicked — one dialog at a time, and a second one raised in the same frame is a call gpui
refuses in its own words:

    unreachable!("Re-entrant window prompting is not supported by GPUI");

So two prompts in one frame need a queue, and that queue is the binding's share. A queue is a
registry, so it can be checked without a window even though a dialog cannot.

**And there is a second reason this row is finishable here.** The queue is usable *on its own*: a
program reads the head, draws it with `ui::rect` / `ui::button`, and answers it. That is a complete
dialog loop with no window in it — the loop a check can reach — and the native dialog is merely the
*other* consumer of the same queue.

**A search that changed what the round knew.** Before writing anything, the picker question was
settled: the five system-dialog capabilities (`open_url`, `prompt_for_paths`, `prompt_for_new_path`,
`reveal_path`, `open_with_system`) are declared on `PlatformWindow`, whose field on `Window` is
`pub(crate)` (`window.rs:823`) and therefore out of reach — but `App` has **public** versions of all
of them (`app.rs:1078`, `1116`, `1129`, `1138`). So CL5–CL8 remain *implementable* and remain blocked
by the native UI, which is what the register already says; the row's "file-picker fallback" clause is
likewise not a binding gap, since `fs::read_dir` reaches a program already (BG7). Said here because a
search that confirms an earlier note is still a search worth recording.

**Three breaks**, one per claim the row makes, each caught:

  * **not FIFO** — any queued prompt answerable, not just the one whose turn it is:

         FAIL answers_come_in_order_and_only_the_head_can_be_answered: panic: the second cannot be
         answered before its turn — that is what a queue is for

  * **a prompt with no answers queued anyway**:

         FAIL a_prompt_with_no_answers_is_refused: panic: a dialog with nothing to click is a dead
         end, so it is not queued at all

  * **answering without taking the prompt out of the queue**:

         FAIL answers_come_in_order_and_only_the_head_can_be_answered: panic: and the second is now up
         FAIL a_queued_prompt_can_be_cancelled_before_its_turn: panic: and the cancelled one never
         takes its turn

**One test was thrown away and rewritten before it was ever run.** The first draft of
`an_answer_raises_its_own_event` held an unfinished placeholder — `prompt_answer(1, 0) == false ||
true`, which is true whatever happens and would have passed against a binding that raised no events
at all. It was caught in review rather than by a break, and the replacement drains the event queue
first so that the only event it reads is the one it caused. Recorded because a tautology in a check
is the same failure as a check that is narrower than it looks, one step earlier.
