AX6 — GPU and device information to the program.

BEFORE THE WORK.

**The row asked for a decision, and the decision turned on a fact that was wrong in the register.**
The obstacle column said "`GpuSpecs` exists on `Window` but is unexposed". It is not:

    $ grep -rn "gpu_specs\|GpuSpecs" ~/.cargo/registry/src/*/gpui-0.2.2/src/window.rs
    4377:    pub fn gpu_specs(&self) -> Option<GpuSpecs> {
    4378:        self.platform_window.gpu_specs()

    $ grep -rn "struct GpuSpecs" -A 10 ~/.cargo/registry/src/*/gpui-0.2.2/src/gpui.rs
    302:pub struct GpuSpecs {
    304:    pub is_software_emulated: bool,
    306:    pub device_name: String,
    308:    pub driver_name: String,
    310:    pub driver_info: String,

A public method returning a public struct of public fields. What is true is that it goes straight to
the platform window, so **only a frame can ask it** — which is what the implementation turns on.

So the answer to the row's question is yes, a program does need it: a diagnostics panel showing
"software rendering: yes" is a real thing a program does, the crate has the element tree for it, and
the alternative — a program guessing its environment — is what a bug report cannot do without. The
row is *implement*, not *record*.

**Four breaks, and one of them passed — which is the round's most useful finding.**

  * **a placeholder for an unasked window** rather than nothing:

        FAIL before_a_frame_has_asked_there_is_no_gpu_to_report: panic: nothing is reported rather
        than guessed: unknown
        FAIL a_field_that_is_not_one_of_the_three_is_empty: panic: there is no vendor field

  * **a window nobody asked reported as software-rendered**:

        FAIL before_a_frame_has_asked_there_is_no_gpu_to_report: panic: and nothing claims a GPU is
        emulated on the CPU when none has been looked at

  * **a name the reader does not answer to, listed in the vocabulary**:

        FAIL the_vocabulary_is_the_three_the_reader_answers_to: panic: the three names, in the order
        a programme would print them: #["device", "driver", "info", "vendor"]

  * **and the one that passed**: making `gpu_field` answer any unknown name with the device — that
    is, making the names not exact — left the whole suite green. The reason is worth writing down:
    outside a frame **there is no record at all**, so `field` returns empty at its `let Some(specs) =
    … else` guard *before the name is ever compared*. Every assertion about exact names was therefore
    vacuous: it would have passed against any matching behaviour whatever.

    The test was rewritten rather than patched: the exactness claim now has a reader behind it that
    *can* fail — `gpui::gpu_fields()`, the vocabulary itself — and the assertion about near-miss
    names stays, because it documents the contract, with the fact that it cannot discriminate
    written into the test's own comment and into the row's residual doubt. That is the eighth time
    this run has found a check narrower than it looked, and the second where the fix was a *new
    reader* rather than a new assertion.
