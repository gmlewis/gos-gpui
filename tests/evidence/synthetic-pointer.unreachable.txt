KM7, MR4, DD1–DD4 — unreachable: the *check* needs an input event nothing can synthesize.

Round 51 closed these six rows in the register. They had been described in `## Unreachable` since
round 31 while their table rows still said `todo`, which is an accounting error rather than a
discovery: the finding was recorded, the row was not. This file is the evidence, re-run in this
round rather than cited from the last one.

`dispatch_keystroke` is a key **down**, and a key-down is the one thing `gpui::send_key` already
synthesizes. `dispatch_action` takes a `Box<dyn Action>`, which R2/R3 forbid a program from making.
`handle_input` and `on_mouse_event` *register* listeners rather than fire them. `dispatch_event` is
the wall: it is `pub`, its parameter `PlatformInput` is public, and its **return type is
`pub(crate)`** — so a call from outside the crate is a compile error, which is how this was found:

    error: type `gpui::window::DispatchEventResult` is private

**2. So the binding can receive anything the platform sends, and synthesize exactly one thing: a
key press.** Every row below is the reception of an event that only a person can produce:

| row | the event its check needs |
|---|---|
| KM7 | a scroll wheel, a mouse exit, a window-level move |
| MR4 | a click variant (`click_count`), a mouse up, a mouse move, an exit, a group hover |
| DD1 | a drag, with a program-owned payload |
| DD2 | a drag in progress, to observe a threshold or a drop-target state |
| DD3 | a file drop from the operating system |
| DD4 | a release *outside* the element that captured the drag |

**3. DD3's own note was checked, and it was wrong about why.** The register's source declared DD3
unreachable because "`FileDropEvent`/`ExternalPaths` exist, `interactive.rs:497,515`, and are
unreachable". They are **not** unreachable — the module is private but wholesale re-exported:

    $ sed -n '27p;85p' ~/.cargo/registry/src/*/gpui-0.2.2/src/gpui.rs
    mod interactive;
    pub use interactive::*;

so `gpui::ExternalPaths` is a nameable type with a public `paths()` accessor, and
`InteractiveElement::on_drop::<ExternalPaths>` is a public method a binding element could call. The
blocker is not the API; it is that the *event* cannot be produced in a check. A file drop reaches a
program only when the platform sends `PlatformInput::FileDrop`, and a real drop is a human dragging a
file onto the window (`platform/mac/window.rs:2370-2406` translate the OS callback).

**What would close all six: one upstream change.** `DispatchEventResult` made `pub` (line 1273).
Then `Window::dispatch_event(PlatformInput::MouseMove(..))` is callable, and with it a synthetic
scroll, move, up, hover or exit — every row above becomes checkable with the instrument
`gpui::send_key` already is. DD3 needs one thing more, and it is small: `PlatformInput::FileDrop` is
translated inside `dispatch_event` (`window.rs:3623-3661`) by setting `cx.active_drag`, so injecting
that variant exercises the whole path.

**This is a reachable capability with an unreachable check, and the register says so.** The
capabilities themselves are not impossible — a person scrolling, dragging or dropping gets them today
— so the row's unreachability is about *this run's* ability to hold them to evidence, not about the
binding. Rows in that state are marked `unreachable` because the register's vocabulary has five
others and all of them would be false: they are not `todo` (the mechanism is reachable, and its shape
is known), not `tested` (nothing was checked), and not `implemented` (nothing was built for them).
CL5–CL8 are the same shape from the other direction: they need a human to *watch* native UI, these
need a human to *move a mouse*.
