BEFORE THE WORK. `gpui::appearance` does not exist at HEAD, so the probe is
abandoned at its first call — nothing on stdout or stderr, exit 124. This row shares
TM4's probe and TM4's before-transcript, which holds the full account; the
appearance-specific part is:

`gpui::Window::appearance()` existed at HEAD (`gpui-0.2.2/src/window.rs:1711`) but
was unexposed, and — unlike most of the register — it was not unexposed because of
the ABI. It is a plain `fn appearance(&self) -> WindowAppearance`, four variants,
all `Copy`. It was simply not written. The only thing in the binding that consulted
it was `app.rs`'s `install_appearance_colors`, which used it to pick a colour set
and never told the program which set it had picked.

The row's other half — "`init_colors` installs light before any window,
`app.rs:328`" — was already fixed before this run: `install_appearance_colors` runs
per window, in the closure that builds each window's root view. See TM4's evidence.
