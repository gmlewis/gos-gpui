What changed, all in `gpui-binding/src/`:

  * `gpu.rs` (new) — one `Specs` per window and `sample`, which asks `window.gpu_specs()` **once** and
    remembers the answer, including the `None` case: the platform having nothing to say is an answer
    too, and it is remembered as one so the question is not asked again. Then `field` (the three
    names, exact), `is_software`, and `names` for the vocabulary.
  * `view.rs` — one line at the top of `begin_frame`: `crate::gpu::sample(win, window)`. Not every
    frame's worth of work, because a driver's name cannot change while a program runs and the call
    is a trip through the platform layer.
  * `lib.rs` — `gpu_field`, `gpu_field_in` (the `_in` twin the store discipline asks of every
    accessor) and `gpu_is_software`.
  * `README.md` — a "What the machine is" section, with the loop a diagnostics panel would write.

**Nothing is reported until a frame has asked**, which is the whole contract this row can check: a
program reading its environment before its first window gets empty strings and `false`, and a
diagnostics panel prints nothing rather than a device name nobody looked up. The `asked` flag is
what makes "asked and the platform said nothing" different from "never asked" *internally*, even
though both read as empty.

Residual doubt, and it is most of the row.

  * **The populated path has never been seen.** No frame has read a real `GpuSpecs`, so no device
    name, driver name or driver version has crossed into the record, and `gpu_is_software()` has
    never answered `true`. A window is needed and this machine's owner has forbidden one; what is
    checked is the empty contract and the vocabulary.
  * **The exactness of `gpu_field`'s matching is not exercised by any check**, as
    `AX6.before.txt` records: outside a frame the record lookup returns before the name is compared.
    `gpu_fields()` gives the *vocabulary* a check that can fail; the matching itself cannot be
    reached here.
  * `sample` treats `None` from `gpu_specs()` as "asked, nothing to say", so a window whose platform
    handle becomes available *later* would never be asked again. `gpu_specs()` is `Option` because
    the platform may not implement it, not because it arrives late, so this is very likely right —
    but it is not something this run could observe either way.
  * The three strings are copied out of gpui's struct rather than referenced, which is deliberate
    (nothing from a window is held past the frame) and costs three small allocations once per window.
  * `info` is the driver's own version text and is passed through unread: the binding does not parse
    it, so a program comparing versions has to do its own.
