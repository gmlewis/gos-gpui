MN1 — submenus.

BEFORE THE WORK.

The row is a grammar problem before it is a binding one. `MenuItem::Submenu` exists upstream and
is simply not exposed, but `set_menus` takes a **flat** list of entry strings, so there was no
way to say which entries are inside a submenu in the first place.

**1. The headless half, against HEAD's binding.**

    $ env -u GOSSAMER_IN_RUNNER gos test tests
      FAIL nesting_reads_back_as_declared: error[GX0002]: name `gpui::menu_tree` is not bound in this scope
      FAIL the_slot_numbering_ignores_the_nesting: error[GX0005]: panic: events entries counted
        in document order, at any depth: #["0:Quit"]
      FAIL an_accelerator_inside_a_submenu_reads_back: error[GX0005]: panic: depth 2 belongs to
        the submenu above it, so only Save is a real item: #[]
      FAIL an_entry_with_no_submenu_above_it_is_reported: error[GX0002]: name `gpui::menu_bad` …
      FAIL two_levels_in_with_only_one_open_is_reported: error[GX0002]: name `gpui::menu_bad` …
      FAIL a_well_formed_menu_reports_nothing: error[GX0002]: name `gpui::menu_bad` …
    test: 190 passed, 6 failed, 683 assertion(s)

Two of those six are **behavioural** rather than unbound names, and they are the honest red for
the grammar: the old parse reads `">events:Open"` as an entry of *kind* `">events"`, knows no such
kind and drops it, so a menu that declares three actions came back with one — `#["0:Quit"]` — and
a menu whose accelerators are all nested came back with none.

**2. The window half.**

    $ timeout -k 5 40 gos run --main-thread tests/gui/mn1_submenu.gos
    exit 124, no output

**3. The breaks.** Four were taken; the second one **passed**, and that is the most useful thing
in this file.

  * **the parse ignores the depth prefix** — every entry treated as depth 0:

        four of the six headless cases fail, the first of them `nesting_reads_back_as_declared`
        at `tests/mn1_submenu_test.gos:30:5`

  * **the build is flat** — a `submenu` entry built as a plain action, so the nesting never
    reaches the platform:

        FAIL MN1 the inner submenu was installed as "1:events:Recent:gpui_binding::Slot0", so the
        nesting did not survive the build

  * **a nested entry loses its own slot** — every entry inside the build wired to slot 0:

        FAIL MN1 the nested entry's own action is "3:events:Recent One:gpui_binding::Slot0", not
        the slot its position implies

  * **and the run of that break that passed**, before the reader was extended. With the menu
    items all wired to slot 0 the probe reported `OK`, because its two slot assertions were
    reading the **keyboard**: `gpui::send_key("cmd-r")` goes through the keymap, which
    `bind_menu_stroke` had bound correctly, so the accelerator fired slot 1 no matter what action
    the *item* carried. A menu whose every item was wired to the same action would have looked
    exactly like one whose items were wired to their own.

    The fix is in the reader rather than the probe: `installed_menu()` now reports the **action**
    each item was given, named by gpui, so the check can see the thing a keystroke cannot stand in
    for. The break was applied again and caught the second time.

That is the fourth time in this run that a check has needed its own failure mode proved rather
than assumed — round 39's break that failed for the wrong reason, round 40's `let _ = raw;` that
captured nothing, round 42's pass that froze a progress of zero, and this one.
