--- why the first attempt at this evidence was worthless, and what it cost to notice

The first attempt reported `ok` on both probes' `run` tiers, which is a green for two programs in
which six names do not exist. The cause is the container's runner cache and it is worth writing
down, because it is a trap that makes any before-run silently meaningless:

`$DHOME/.cache/gossamer/runners/<fingerprint>/` holds a `runner/` tree and its rust target
directory, and the fingerprint is taken from the binding's **path declaration** — `[rust-bindings]`
in `project.toml` — and not from the binding's source. Two different `gpui-binding/` trees at the
same declared path therefore share one cargo target directory. `scripts/gosbox.sh` stages the tree
into `/work` with `rsync -a`, which preserves mtimes; a head-src tree staged from
`$HOME/.cache/learn-gpui/dw12-head-src` therefore arrives with its sources **older** than the
`librunner.rlib` the working tree's last build left in that shared target directory, cargo declares
the crate fresh, and the runner is linked against the **working** binding — the one that has all six
names. The probe passes, and it passes for a tree it never compiled.

The fix is to `touch` the staged tree's binding sources before the tier run, which the rerun above
does (`touch gpui-binding/Cargo.toml gpui-binding/src/*.rs`, printed as the `touched:` line at the
head of the batch's output). The reds above are the same two probes run that way; the `FAIL run:
exited 124` is the self-check, because a tier that never reaches `quit()` cannot have been answered
by a build that resolves the names.

**The corollary is a scheduling rule, not a one-off fix: a working-tree container run must never be
interleaved between head-src container runs.** The shared target directory holds whichever binding
was compiled into it last, and the tier that follows inherits it.
