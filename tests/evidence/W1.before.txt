BEFORE THE WORK. Two observations, both from a pristine copy of this project at
HEAD (`git archive HEAD` into /tmp/gpui-before, so nothing in this tree was
touched).

1. The unresolved symbol. The headless half of the same capability — the last
   assertion of `tests/w2_store_scope.gos`, which asks `gpui::window_id()` what
   window it is in — was run against the pristine tree:

   Output:

     call stack (outermost first):
       at outside_a_frame_there_is_no_window (tests/w2_store_scope.gos:57:12)
   test: 0 passed, 1 failed, 0 assertion(s), 0 ignored, 0 skipped, 0 doc-test(s), across 1 file(s), 0 with no tests

   The full four-failure transcript is in `W2.before.txt`; this is the one line
   that belongs to W1.

2. The GUI probe itself. Run against the pristine tree:

       cd /tmp/gpui-before
       timeout -k 5 60 gos run --main-thread tests/gui/w1_window_id.gos

   Output: nothing on stdout or stderr, and exit 124 — the timeout killed it.

   Re-run later with the runner's build lock cleared first, to be sure the hang
   was the probe and not the lock (see "The stale build lock"): still nothing,
   still 124. So this transcript is the probe.

   The window opens, the view callback fails on its very first call, and the
   binding catches the failure at its boundary the way it always does: the error
   becomes a card drawn in the window, and the callback body never runs past it.
   The detail that makes it a *hang* rather than a failure is that
   `gpui::animate()`, which every other path in the probe reaches, is below the
   failing call: no later frame is ever asked for, the window goes idle, and the
   `gpui::quit()` on some later frame never happens. A probe whose first call is
   unbound therefore has no output at all, which is why `scripts/tiers.sh` bounds
   every run and reaps the runner afterwards — a probe that leaves a window open
   is not a check.

The capability is what is missing, not the plumbing: `view.rs` kept one
process-global arena with one `ROOT` cell and one `FRAME` counter, `store.rs`
one process-global `Store`, and nothing anywhere held a window's identity, so
"which window is this?" had no answer for a view callback to read.
