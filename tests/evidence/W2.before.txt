The unresolved symbol is the point, and it is the honest half of the finding.
Before the work there was no way to *address* a window at all — `store.rs` held
one process-global `Store` behind one `LazyLock<Mutex<Store>>`, so "which
window's state is this?" had no answer, and no test could ask. The other half is
recorded in the row: the scoping itself.

One detail worth keeping, because it cost a round: `gos check` does **not**
catch this. `gos check tests/w2_store_scope.gos` answers `check: ok (1 items
typed)` on both trees — the checker types the program but does not resolve the
binding's names, so the failure only appears when a tier actually runs. The
binding's Rust compile errors are a different thing, and those `gos check` does
surface.
