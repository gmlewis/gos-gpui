DW3 — the window's own pixels are not reachable in the container.

Measured 2026-10-07 in gosbox:1 (Xvfb :99, 1600x1200, openbox, gpui 0.2.2 with the
`x11` feature — which is blade-graphics on Vulkan, software-rendered by lavapipe).

The program: tests/dw3cap/hold_flash.gos, a window that composes "nihao" and then
repaints its whole background a different colour every frame, so every frame damages
the entire client area. Held open, then captured:

    wid=$(xdotool search --name 'dw3 capture - flash' | head -1)
    eval "$(xdotool getwindowgeometry --shell $wid)"
    import -window root -crop ${WIDTH}x${HEIGHT}+${X}+${Y} +repage out.png

What came back:

    geometry 480x240+561+510        the window is mapped, correctly sized, and titled
                                    — openbox's frame around it is in the capture, with
                                    the title drawn in it, so the capture path is reading
                                    the X framebuffer.

    histogram of the client area (480x240):
        112582  #000000   black      the whole client area
          1187  #585A5D   grey  \
           479  #FFFFFF   white  |  ~2,600 pixels in a two-or-three row strip along the
           478  #CFD0D1   grey  |  client area's bottom edge — the window manager's own
           474  #EAEBEC   grey  /  resize grip, drawn by the server, not by the program.

Not one pixel of the program's own drawing is there: not the #111111 background column,
not the input field's #1e1e2e box, not a glyph, not the caret. The same histogram came
back from a run whose window was *not* flashing (an idle window that had been painting
for thirty seconds), so this is not damage tracking and not a matter of which frame was
caught — the client's presented image does not reach the framebuffer XGetImage reads.

`tests/evidence/DW3.nocapture.png` is that capture: the framed, titled, correctly sized
window, with an empty black client area.

So the container witnesses *behaviour* — what a key does, what the text is, what the
marked range is — and not *pixels*. Every DW3 claim below is behavioural for that reason,
and the drawn half of the row (the composing word underlined) is recorded as not
witnessed rather than asserted: see the DW3 row in CAPABILITIES.md.
