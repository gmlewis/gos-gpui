KM5 — `observe_keystrokes` must see keys an element handled.

BEFORE THE WORK. Against a pristine copy of this project at HEAD:

    cd /tmp/gpui-before
    timeout -k 5 40 gos run --main-thread tests/gui/km5_observed_keys.gos

    exit 124, no output

**A weak red, and one with a caveat that will not be hidden.** It is weak for a
reason that is itself the row: the probe produces its keystrokes with
`gpui::send_key`, which does not exist at HEAD, so the callback is abandoned at frame 4
and the window goes idle. There is no stronger transcript to be had, because at HEAD
there is no way to produce a key event at all — that absence is why the row could not be
checked before this round, and why the round began by adding `send_key`.

The caveat: this transcript was taken **while the screen was locked**, so a stall is
over-determined — the abandoned callback and the unpainted window both produce it. The
reasoning above stands on its own (an unbound name abandons the callback above the
`animate()` that would ask for the next frame, so the window idles on any display), but
the observation is confounded and is recorded as such. See "The screen is locked".

The mechanism the row is about, read from the source: a key event is dispatched down the
tree from the root to the focused element and then back up
(`gpui-0.2.2/src/window.rs:3878-3906`), and `cx.stop_propagation()` in a handler ends that
walk — after which `finish_dispatch_key_event` returns before it ever reaches
`dispatch_keystroke_observers` (`window.rs:3861-3869`). The text editor's handler ends
with `cx.stop_propagation()` (`gpui-binding/src/editor.rs:445`) for every key it consumes,
so `cx.observe_keystrokes` — which is what this bound until now — could not see the keys a
program most wants to watch: backspace, the arrows, and the rest.

The break, which is the evidence that matters here: register the window root's listener
in the bubble phase instead of the capture phase, so it runs after the editor's handler
rather than before it,

    FAIL KM5 the editor handled "a" and backspace, and the observer saw 1 of them: a

One of two — the key nothing handled arrives, the key the editor handled does not, which
is exactly the gap the row names.
