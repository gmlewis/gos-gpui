AX2 — program-authored `impl EntityInputHandler` / `impl InputHandler` / `impl AssetSource`:
UNREACHABLE, and the three fail for the same reason as AX1 with one difference worth
stating: two of them have a *working substitute inside the binding*, and one does not.

The same compile error as `AX1.unreachable.txt`, because it is the same wall — a host
trait cannot be named in an `impl` block:

    error[GT0070]: unknown trait `Render` in `impl Render for Thing`
      = help: nothing declares `Render`, so the block's methods are inherent methods on
              `Thing` under a header that promises a contract

and the same ABI rules forbid carrying one:

    $ sed -n '292p;294p' $GOSSAMER_ROOT/crates/gossamer-binding/src/native.rs
        type Input: Copy;
        type Output: Copy + Default;

The difference is *when* the host calls them. `EntityInputHandler::replace_text_in_range`
and `InputHandler::dispatch_input` are called by the platform while a key is being
handled — `window.handle_input` — and `AssetSource::load` is called by gpui's asset loader
when an image is first painted. Both happen inside frames the program does not own, and
both are invoked through `Rc<dyn Trait>`-shaped values that stay in Rust:

    $ grep -n "take_input_handler" ~/.cargo/registry/src/*/gpui-0.2.2/src/window.rs | head -2
    .../src/window.rs:3559:            && let Some(mut input_handler) = self.platform_window.take_input_handler()

A trait object is not a value the ABI has a shape for, so the platform can only ever be
handed an implementation the *binding* wrote.

**Why this is terminal, and what closes the capability anyway.** The register says to say
which rows substitute for it, so:

  * `EntityInputHandler` and `InputHandler` → **DW1–DW4**: `gpui-binding/src/editor.rs` is a
    Rust-owned `TextEditor` implementing both, with a caret, selection, clipboard and
    IME, exposed as the narrow Gossamer-facing knob `ui::editor(key, placeholder, style)`.
    That is the route-D answer to this half of the row and it is already built.
  * `AssetSource` → **DW7**, which is *not* built: `image_request` is promised in
    `PORTING.md` §6 and absent from `lib.rs`. So this row's third name is unreachable for
    the same structural reason and its substitute is a gap that is still open.
  * A future toolchain change that closes this row: the same one as AX1 — a `'static`
    vtable that can cross the ABI — plus, for `AssetSource`, gpui making the loader
    reachable as a value rather than a trait.

Note that "unreachable" here is about *program-authored* implementations. The platform
input handler is exercised every day through the editor; what cannot exist is a program
handing the platform its own.
