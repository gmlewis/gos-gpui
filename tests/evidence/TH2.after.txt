TH2 — observe appearance changes while running.

AFTER THE WORK.

The probe is one that **cannot be run plainly**: it waits for the system appearance to
change, and nothing in-process can cause that. It is run under
`scripts/appearance-toggle.sh`, which flips the machine's appearance part-way through and
puts it back under a `trap` on EXIT/INT/TERM.

**The `check` tier**, which compiles the binding the way the toolchain does:

    $ env -u GOSSAMER_IN_RUNNER gos check tests/gui/th2_appearance_change.gos
    check: ok (2 items typed)

**The interpreter tier:**

    $ ./scripts/appearance-toggle.sh gos run --main-thread tests/gui/th2_appearance_change.gos
    appearance: flipping from 'Dark' for the program to observe
    OK TH2 the appearance changed from "dark" to "light" while the program ran, and the
    observer reported it

    appearance: was style='Dark' autoswitch='<unset>'
    appearance: now style='Dark' autoswitch='<unset>'
    appearance: restored exactly

**A compiled tier** (the release binary, built with `CC=tools/cc-gpui.sh`, this being
the tier where a callback that outlives the binding call is the thing that can go
wrong):

    $ CC="$PWD/tools/cc-gpui.sh" gos build --release tests/gui/th2_appearance_change.gos
    build: 7553720B native executable at target/release/learn-gpui
    $ ./scripts/appearance-toggle.sh timeout -k 5 35 ./target/release/learn-gpui
    appearance: flipping from 'Dark' for the program to observe
    OK TH2 the appearance changed from "dark" to "light" while the program ran, and the
    observer reported it

    appearance: was style='Dark' autoswitch='<unset>'
    appearance: now style='Dark' autoswitch='<unset>'
    appearance: restored exactly

The machine is `Dark` with the auto-switch unset, exactly as it was found, before and
after every one of these runs.

Headless — `env -u GOSSAMER_IN_RUNNER gos test tests`: `145 passed, 0 failed, 522
assertion(s)`. Regression: `regress: silent — 27 checked, no output from any run`.

What changed, all in `gpui-binding/src/`:

  * `app.rs` — `Request::ObserveAppearance { id }`, installed once per (window, id)
    through `Context::observe_window_appearance` and `.detach()`, which is the shape
    WH6's bounds observer established. The callback reports
    `view::appearance_of(window.appearance())` — the same two words
    `gpui::appearance` answers — and asks its own window for a frame.
  * `view.rs` — `appearance_of` becomes `pub` so the observer can use the one
    appearance-to-word mapping rather than a second copy of it.
  * `lib.rs` — `gpui::observe_appearance(id)` beside `gpui::appearance`, documented as
    the running half of it.
  * `scripts/appearance-toggle.sh` — new. Reads `AppleInterfaceStyle` **and**
    `AppleInterfaceStyleSwitchesAutomatically` (the "Auto" switch is a different
    setting and survives a `dark mode` write), runs the command, flips, and restores
    both under a `trap`, then verifies both by reading them back and exits 3 if either
    differs.

**Three tiers were run, and the machine's appearance was flipped three times — one
more than the two I had asked about**, because the compiled tier's first attempt had to
be retried. `run --no-jit` and `build` (debug) were deliberately not run under the
toggle, because each is another change to the machine's own appearance setting; the
check is a callback registration whose only tier-sensitive part is whether the callback
survives the binding call, and the compiled tier exercises that. `run --no-jit` is the
interpreter ABI a second time. If a future round wants them, the command is one line:
`./scripts/appearance-toggle.sh gos run --main-thread --no-jit tests/gui/th2_appearance_change.gos`.

Residual doubt, and it is more than usual for this row.

  * **The compiled tier is flaky here, and one attempt was lost to it.** The first
    release-tier run did not finish: the wrapper flipped, the window stopped being
    painted, and a probe that waits on frames never reached its verdict — killed after
    five minutes by the calling tool, with its block-buffered verdict lost, exactly the
    trap this ledger records under the stale build lock and the locked screen. Bounded
    with `timeout`, the same binary passed first try. So the row's evidence is one
    clean interpreter run and one clean compiled run, with a failed compiled attempt
    behind them that was the environment and not the code — and a check whose failure
    mode is silence, which is worth knowing before trusting a red one.
  * **The wrapper changes the user's machine.** It restores, verifies and is trapped,
    but a SIGKILL between the flip and the trap would leave the appearance flipped.
    This is why the row was checked three times and not five, and why the wrapper is a
    separate script rather than something the probe does to itself.
  * **Only the two-valued appearance is reported.** `light`/`dark`, the same words
    `gpui::appearance` answers and for the same reason: gpui's `VibrantLight` and
    `VibrantDark` are folded into them, so a program needing four values cannot get
    them (TH1's doubt, inherited).
  * Whether the observer fires while a *modal* or full-screen window owns the display
    is untested; the platform callback is per view and unqualified, but that is read
    from the source rather than measured.
