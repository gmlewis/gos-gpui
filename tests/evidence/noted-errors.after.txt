noted_errors — green on all five tiers, and both harnesses taught to read its header
Tiers: check, run, run --no-jit, build, build --release — all five, and no process
left alive.

THE GREEN. The same probe, the break reverted, `scripts/tiers.sh` driving all five:

    $ DSH_ALLOW_WINDOWS=1 ./scripts/tiers.sh tests/gui/noted_errors.gos
    === check ===
    check: ok (1 items typed)

    === run (interpreter) (exit 0) ===
    NOTED before anything went wrong: 0 message(s)
    gpui: unknown style tokens: notatoken=7
    gpui: noted: unknown style tokens: notatoken=7
    NOTED the program can read what the person would see: #["unknown style tokens: notatoken=7"]
    OK noted_errors the banner's messages reach the program, so a silent empty window is no longer invisible

`run --no-jit`, `build -> ./target/debug/learn-gpui` and
`release -> ./target/release/learn-gpui` each print the same four lines and exit 0.

FOUR THINGS ARE THE RESULT, AND THEY ARE DIFFERENT THINGS.

  1. **The program can read the banner.** `gpui::noted_errors()` answers
     `#["unknown style tokens: notatoken=7"]` — the same message the person would
     see drawn in the window, as data a check can act on.
  2. **stderr carries it too, when asked.** `gpui: noted: unknown style tokens:
     notatoken=7` appears only with `GOSSAMER_NOTED_ERRORS=1` in the environment.
     That is the half a *suite* can see, and it is opt-in so an example run for its
     own sake stays silent.
  3. **Before anything goes wrong the list is empty** — `0 message(s)` on frame 1,
     so the channel is not simply reporting everything.
  4. **The unknown token is reported by the binding's own style reader**
     (`gpui: unknown style tokens: notatoken=7`, printed by the parser) as well as
     through the noted channel. Two paths, one message, and the probe is what says
     they agree.

THE HEADER, AND WHY TWO SCRIPTS READ IT. A probe whose whole subject is the
noted-error channel has to be allowed to note an error, or the suites fail it for
doing its job. It declares that in its own header:

    // noted: expected — this probe's whole subject is the channel, so the note it causes
    // is the result rather than a finding.

`scripts/probes.sh` already read that line. **`scripts/tiers.sh` did not, and this is
what running it found:** the probe passed all five tiers and `tiers` still exited
**1** —

    tiers: the binding noted 4 message(s) — not a clean run:
        run (interpreter): gpui: noted: unknown style tokens: notatoken=7
        run --no-jit:      gpui: noted: unknown style tokens: notatoken=7
        build -> ...:      gpui: noted: unknown style tokens: notatoken=7
        release -> ...:    gpui: noted: unknown style tokens: notatoken=7

— which would have read as "the channel is broken" when the channel was doing
exactly what the probe asked it to. `scripts/tiers.sh` now reads the same header, and
says so rather than going quiet:

    tiers: the binding noted 1 message(s), which is this program's result rather than a
    finding — it exists to prove the channel:
        run (interpreter): gpui: noted: unknown style tokens: notatoken=7
    === exit=0 ===

**The exemption is by name, not by rule.** A program that notes an error *without*
that header still fails `tiers` and still fails `probes`, which is the whole point
of the channel: `examples/02_data_table.gos` was failed by nothing for days because
a note was invisible, and the fix is worthless if a note becomes ignorable. Only
`tests/gui/noted_errors.gos` carries the line.

WHAT IS STILL NOT CHECKED BY THIS PROBE: that the banner is *drawn*. The probe
proves the messages reach the program and stderr; it does not look at the window.
Nothing here needs that, but it is the honest boundary of what green means on this
page.
