accelerator-binding half by the behavioural red in `KM3.before.txt`

What changed, all in `gpui-binding/src/`:

  * `app.rs` — `MenuEntry` gains `stroke`; `menu_plan` reads the optional third part
    of an `events` entry (`"events:Save:cmd-s"`), leaving the slot numbering alone
    (that is MN3's rule, and this row rides on it); `menu_accelerators` reads the
    declarations back as `"<slot>:<stroke>"`; `bind_menu_stroke` binds a declared
    stroke to its entry's own slot action, the arms mirroring `push_menu_action` so a
    click and its accelerator always drive the same action; the `SetMenus` arm binds
    **before** `cx.set_menus`, because the platform is handed the keymap when the
    menu is installed and that is where a key equivalent comes from. An unparseable
    stroke is reported as `"~keybind.bad|<stroke>"` instead of panicking the window
    away through `KeyBinding::new`.
  * `lib.rs` — `set_menus`'s doc promises the third part, the fact that an
    accelerator is a binding rather than an item field, and the `~keybind.bad`
    report; `gpui::menu_accelerators` added beside `gpui::menu_slots`.
  * The tests: `tests/km3_menu_accelerator_test.gos` (four headless cases, one of
    which pins `menu_slots`' numbering against the new third part) and
    `tests/gui/km3_menu_accelerator.gos`.

Residual doubt. **The drawn accelerator is not checked.** That the native menu bar
shows `⌘S` beside `Save` is the capability's other half, and it is a pixel claim on a
machine with no Screen Recording permission — what is checked is the binding the
platform reads to draw it, which is one call away from the drawing and not the same
thing. Only one stroke is probed; slots 1–7 and the `Slot0` overflow arm are the same
code with a different constant. A `quits` entry takes no accelerator by construction
(⌘Q is already bound to quitting), so an accelerator on the quit item is not
expressible — upstream's own menu is `os_action`-shaped there. And the probe installs
a real menu bar over the desktop for the length of its run, which is the same
nuisance `scripts/probes` already documents.
