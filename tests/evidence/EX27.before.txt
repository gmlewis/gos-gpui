Round 105 — `27_window`'s sub-window placement, and what it was deleted against.

Command: ./scripts/gosbox.sh run tests/gui/zz_ex27_red.gos

`examples/27_window.gos` carried this deviation:

    //   * Sub-window placement. Upstream asks for `Bounds::centered(None, ..)`,
    //     which centres on the primary display; this port computes the same
    //     origin itself from `gpui::display_field(0, ..)` and passes it as x and
    //     y, because `place=center` was parsed and then ignored — `options.rs`
    //     compared it in an `if` whose two arms were the same expression.

Both of its clauses are false at HEAD, and in the same direction. The second is
the plainest: `place=center` is not ignored. `gpui-binding/src/options.rs` has

    let place = if options.place.as_deref() == Some("center") {
        WindowPlacement::Centered(Bounds::centered(display, extent, cx))
    } else {
        WindowPlacement::Coordinates(point(px(x), px(y)))
    };

with `display` resolved from `options.display` — for the port's spec, which leaves
`display=` out, that is `None`, and `Bounds::centered(None, extent, cx)` is
upstream's own call, argument for argument. WH4's round fixed the arms; this bullet
described the state before it.

The first clause is false by the port's own reasoning. `centred()` was:

    fn centred(width: f64, height: f64) -> (f64, f64) {
        let dx = gpui::display_field(0, "x")
        let dy = gpui::display_field(0, "y")
        let dw = gpui::display_field(0, "w")
        let dh = gpui::display_field(0, "h")
        return (dx + dw / 2.0 - width / 2.0, dy + dh / 2.0 - height / 2.0)
    }

`gpui::display_field(0, ..)` is the *first* display `cx.displays()` returned, and
`gpui::view::displays()` is filled from `cx.displays()` in order
(`gpui-binding/src/view.rs:1213-1226`), so index 0 is the primary — the same screen
`Bounds::centered(None, ..)` resolves to. The arithmetic is the same arithmetic. The
bullet's claim that the port "computes the same origin itself" was true; the claim
that it had to, because the option was ignored, was not. And on a Mac either way
gives the same rectangle, because `Display::bounds().origin` is `(0, 0)` for every
display — which `25_window_positioning.gos`'s own first bullet says outright.

So the workaround was removed: `centred()` is gone, `open_sub`'s tail is

    gpui::open_window(title, 0.0, 0.0, 300.0, 300.0, f"{options} place=center")

and the bullet went with it.

`was_place` in `tests/gui/zz_ex27_red.gos` is a transcription of the deleted
workaround, kept in the probe so this red can be reproduced from the probe alone.
The probe is not `examples/27_window.gos` and cannot be: a probe cannot import
`examples/ui/mod.gos` — `gos check` answers `error[GR0005]: module \`ui\` does not
exist` for a file outside `examples/` — so the port's spec is transcribed. That is
the one soft joint, exactly as it is in `tests/gui/dt1_thumb_track.gos` and
`tests/gui/mp3_drag_threshold.gos`.

The red, verbatim (the `FAIL … no verdict` line is the suite's — a probe that has
failed prints no `OK ` for it to find, which is the point):

    $ ./scripts/gosbox.sh run tests/gui/zz_ex27_red.gos
    FAIL   tests/gui/zz_ex27_red.gos: exited 0 — no verdict
           FAIL EX27 the child was opened with a placement of "", not the `center` upstream's Bounds::centered(None, ..) asks for

One finding, and it is the bullet's own claim: the window `open_sub` opened carried
no placement at all. The size check above it passes — the old spec passed 300x300
too, because the size was never the workaround — so the failure is isolated to the
placement and nothing else.

The probe measures the **asked-for** half, and says so. Where the window *landed* is
not checkable in the container: gpui's X11 backend sets no ICCCM position hints, so
openbox places the window itself, which is why `wh4_display_place.gos` declares
`// linux:` and is skipped there. The asked-for half — the value that goes into
`WindowOptions`, read back through `gpui::window_option` — is checkable on every
tier, and it is the whole of what this binding does with a spec.
