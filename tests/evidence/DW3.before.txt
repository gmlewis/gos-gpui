DW3 — the before-transcript, and why it took two runs.

Measured 2026-10-07 in gosbox:1 against **pristine HEAD** (`git archive HEAD | tar -x`
into a scratch tree, rsynced to its own stage, the container's own /tool and /gos).
The probe the row keeps cannot compile there: `gpui::compose` and `gpui::composing` do
not exist at HEAD, so it was stripped to what HEAD can run — the same frame script, the
same keys, the same assertions on what the field ends up holding.

  docker run … -w /work gosbox:1 bash -lc \
    "export PATH=…; timeout -k 5 600 /tool/bin/gos run --main-thread tests/gui/dw3-before.gos"

--- Run 1: the stripped probe as it stands. Exit 0, and every assertion red:

    FAIL DW3 the two keys it was sent gave "", not "ac"
    FAIL DW3 typing after `left` gave "", not "abc": the field appends rather than inserting at the caret
    FAIL DW3 enter raised 0 submit events, not one

  Not one key landed. At HEAD `ui::input` is focused **only by a click** — its
  `track_focus` handle is handed to `window.focus` from an `on_click` and nowhere else —
  and a container has no way to click. That is true and it is worth knowing: a field at
  HEAD is unreachable without a pointer. But it is not the row's claim, and a red that
  is really "the probe could not press the button" is not evidence about the engine.

--- Run 2: the same probe, with `gpui::focus("field")` on frame 2 first — the call a
    program makes to open a dialog with its first field ready — so focus is out of the
    way and what is left is the field itself:

    FAIL DW3 typing after `left` gave "acb", not "abc": the field appends rather than inserting at the caret
    FAIL DW3 cmd-a then backspace left "ac", not an empty field

  Both are the engine, exactly as the row predicted. `"ac"` came back right, so the keys
  did land this time. Then `left` moved nothing — the old field had no caret to move, so
  `b` went on the end of `acb` — and `cmd-a` selected nothing, so backspace took one
  character off the end instead of the field.

Both runs are kept below verbatim. They are temporary instruments: neither compiles
against the tree the row keeps (no `gpui::compose`, no `gpui::composing`), which is why
they are transcribed here rather than filed under tests/gui/ beside the probe they mirror.

===================================================================
dw3-before.gos (run 1)
===================================================================
// DW3, stripped to what a HEAD build can even compile: the caret, the selection and the
// composing range are gone, because HEAD's `ui::input` has none of them and no
// `gpui::compose`/`gpui::composing` to ask about. What is left is the two things a
// hand-rolled key loop can still be caught being wrong about, and this reports both
// rather than stopping at the first.
//
//   gos run --main-thread tests/gui/dw3-before.gos

use gpui
use std::process

fn main() {
    let outcome = gpui::run("dw3 before - the hand-rolled field", 480.0, 240.0, || {
        let f = gpui::frame()

        if f == 3 {
            gpui::send_key("a")
            gpui::send_key("c")
        }
        if f == 5 {
            gpui::set_text("dw3.typed", gpui::state_text("field", ""))
            gpui::send_key("left")
            gpui::send_key("b")
        }
        if f == 7 {
            gpui::set_text("dw3.inserted", gpui::state_text("field", ""))
            gpui::send_key("cmd-a")
            gpui::send_key("backspace")
        }
        if f == 9 {
            gpui::set_text("dw3.cleared", gpui::state_text("field", ""))
            gpui::send_key("enter")
        }
        if f >= 11 {
            let typed = gpui::state_text("dw3.typed", "")
            let inserted = gpui::state_text("dw3.inserted", "")
            let cleared = gpui::state_text("dw3.cleared", "")

            let mut submitted = 0
            for event in gpui::take_events() {
                let id, what = gpui::event_parts(event)
                if id == "field" && what == "submit" {
                    submitted = submitted + 1
                }
            }

            let mut bad = 0
            if typed != "ac" {
                println(f"FAIL DW3 the two keys it was sent gave \"{typed}\", not \"ac\"")
                bad = bad + 1
            }
            if inserted != "abc" {
                println(f"FAIL DW3 typing after `left` gave \"{inserted}\", not \"abc\": the field appends rather than inserting at the caret")
                bad = bad + 1
            }
            if cleared != "" {
                println(f"FAIL DW3 cmd-a then backspace left \"{cleared}\", not an empty field")
                bad = bad + 1
            }
            if submitted != 1 {
                println(f"FAIL DW3 enter raised {submitted} submit events, not one")
                bad = bad + 1
            }
            if bad == 0 {
                println(f"OK DW3 the hand-rolled field took \"{typed}\", inserted to \"{inserted}\", cleared to \"{cleared}\" and raised its submit event")
            }
            gpui::quit()
        }

        gpui::animate()
        let root = gpui::column("p=12 gap=10 size=full bg=#111111")
        gpui::child(root, gpui::text("input field", "color=#ffffff"))
        gpui::child(root, gpui::input("field", "type here", "p=6 w=320 bg=#1e1e2e"))
        gpui::root(root)
    })

    if let Err(problem) = outcome {
        eprintln(f"FAIL DW3 gpui::run stopped with an error: {problem}")
        process::exit(1)
    }
}

Round 87's deliberate break — the load-bearing line, proven rather than asserted
===================================================================

The two runs above establish what HEAD could not do. This one establishes *where* the
new behaviour comes from: `EditorElement::paint` registering the element with the
window's input system, in `gpui-binding/src/editor.rs`:

    window.handle_input(
        &focus_handle,
        ElementInputHandler::new(bounds, self.input.clone()),
        cx,
    );

Replaced with a no-op (`let _ = &focus_handle;`), and nothing else changed:

    $ GOSBOX_TIMEOUT=200 ./scripts/gosbox.sh run tests/gui/dw3_input_ime.gos
    FAIL   tests/gui/dw3_input_ime.gos: exited 0 — no verdict
           FAIL DW3 the field did not take the two keys it was sent; it holds ""

Restored (`git diff --stat` back to `209 insertions(+), 13 deletions(-)`, the same as
before the break), the probe is green again:

    $ GOSBOX_TIMEOUT=200 ./scripts/gosbox.sh run tests/gui/dw3_input_ime.gos
    ok     tests/gui/dw3_input_ime.gos: OK DW3 the field inserted at the caret ("ac" then "abc"), cmd-a and
           backspace cleared it, a composing "nihao" was readable and replaced by the next key ("x", no longer
           composing), and enter and escape raised their own events

What that shows is not "the widget is broken if you delete a line". It shows that the
probe's text is *delivered through the platform's input handler* and through no other
path: deleting the registration leaves the field holding an empty string, with the keys
going nowhere, which is precisely what the row's first before-run diagnosed at HEAD for
the same reason.

**A hazard worth writing down, found while doing this.** The first attempt at the break
reported `exited 124 — no verdict` and printed *nothing at all*, twice, including after
the tree was restored. The cause was not the break: a throwaway container killed at a
120s timeout had left `runners/eb43bebcecce/.gos-build.lock` holding pid 40 in the
persistent `/root` volume, and the next `gos` polled it until the bound expired. The
lock was reaped, and `scripts/gosbox.sh` now reaps one itself before every run, bulk pass
and tier — the same courtesy `scripts/regress.sh`, `probes.sh` and `tiers.sh` already
extend to the Mac's cache, which is a *different* cache.
