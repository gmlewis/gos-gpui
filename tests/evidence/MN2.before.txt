MN2 — OS actions and the application/dock menu.

BEFORE THE WORK.

Three reds, and then the row turning out to be more checkable than the register implied.

**1. The headless half, against HEAD's binding.**

The first run had **four** failures, and all four were behavioural rather than unresolved names —
the old parse knows four kinds and reads `"os:Copy:copy"` and `"services:Services"` as the unknown
kinds `"os"` and `"services"`, dropping them:

    $ env -u GOSSAMER_IN_RUNNER gos test tests
      FAIL an_os_action_reads_back_as_its_own_kind: panic: three entries, got 1
      FAIL only_the_actions_take_slots: panic: actions counted, menus not: #["0:Quit"]
      FAIL the_six_selectors_are_the_ones_it_knows: panic: all six are known: 0
      FAIL the_nesting_still_applies_to_both: panic: vec index out of bounds: the len is 1
    test: 205 passed, 4 failed, 728 assertion(s)

**2. A fifth failure the round had to *create*, because one of the four passed for the wrong
reason.** `a_selector_it_does_not_know_is_reported` was green at HEAD: `"os:Copy:nosuch"` was
reported as a misplaced entry, which is the right answer arrived at by the wrong route (the whole
kind was unknown, not the selector). The test was given the other direction as well —

    let known = gpui::menu_bad(#["os:Copy:copy", "os:Select All:selectAll"])
    assert(known.len() == 0, f"both are selectors it knows: {known}")

— which fails on the old parse and is what makes the pair mean something:

    FAIL a_selector_it_does_not_know_is_reported: panic: both are selectors it knows:
    #["os:Copy:copy", "os:Select All:selectAll"]

**3. The window half**, `exit 124`, no output, at the unbound readers.

**4. Four breaks**, each applied alone and each caught:

  * **the selector dropped** — an `"os:"` entry built as an ordinary action:

        FAIL MN2 the platform has 0 system action(s), not the 2 declared: #[]

  * **the Services menu built as an ordinary submenu** — so the system never fills it:

        FAIL MN2 the Services menu was installed as "2:submenu:Services:", not as a system menu

  * **an OS action taking no slot** — `menu_slots` counting only `"events"`:

        only_the_actions_take_slots fails: `actions counted, menus not: #["1:Quit"]`

  * and **two probes' own expectations were wrong** before the code was: the headless cases wrote
    `"os:Copy:text"` where the selector should have been `copy`, and the window probe counted the
    menu bar's own line as item zero and looked for Services one place too early. Both were the
    check being wrong, not the binding, and both are recorded here rather than quietly fixed.
