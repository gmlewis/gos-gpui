W8 — menus wired to the window that renders, not the first.

AFTER THE WORK. **Two windows, no clicks, and the routing visible.**

    $ DSH_ALLOW_WINDOWS=1 ./scripts/run-once.sh tests/gui/w8_menu_owner.gos 45
    window-guard: windows ALLOWED (DSH_ALLOW_WINDOWS=1)
    W8 the first window reports "0:menu:w8.first:" and the second reports "0:menu:w8.second:"
    OK W8 each window was given its own menu, so the menu follows the window that renders

Each window was asked what menu *it* was given — `gpui::installed_menu()` answers for the window whose callback
is running — and they differ, which is the row. Before the fix the second window's `set_menus` landed on the
first window, so window 2's record stayed empty and window 1's named the second menu; those are the probe's two
FAIL cases, and both name the defect.

**The row's own doubt was wrong, and this file is the correction.** It said the routing could not be exercised
because a menu click cannot be synthesized. That is true of the *click* and false of the *wiring*, which is what
the row's title claims. The row sat `implemented` from round 20 to round 74 on a doubt that its own reader could
have answered all along.

Residual doubt: the action half remains unexercised — that clicking an item delivers it to the window whose menu
it was. A *keystroke* accelerator might reach the same path one day, since keys are the one input this binding
can synthesize. Tiers: `check` and `run`.
