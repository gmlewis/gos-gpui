What changed, all in `gpui-binding/src/`:

  * `settings.rs` (new) — the store: `load`/`store` over one `key=value` per line, `set`, `get`,
    `forget`, `remember_bounds`, `bounds`, `field`, and a `number` that leaves off a trailing
    `.0` because a settings file is read by people. A file that is not there, and a line that is
    not a `key=value`, both contribute nothing rather than failing.
  * `options.rs` — `Options.pos` and the `pos=x,y` token, which also sets `place=at` so a later
    `place=center` wins as it would for any other token; `build` takes the position from the
    spec when there is one. **This is what makes the row's restore half complete**: `gpui::run`
    takes a title, a size and a callback and no position, so without it a remembered position
    could never be restored to the *first* window, only to one opened with `open_window`.
  * `store.rs` / `app.rs` — `Request::SaveWindowState`, which reads the live window's bounds and
    records them through the same `remember_bounds` a program calls when it reads them itself.
  * `lib.rs` — `settings_set`, `settings_get`, `settings_forget`, `remember_window_state`,
    `saved_bounds`, `saved_field`, `save_window_state`.
  * `README.md` — a "Settings that survive a restart" section with the whole pattern, and the
    `pos=` token in it.

**A half-written window state is nothing**, and that is the row's one design decision worth
naming: three of four numbers is not a window at 0,0, it is a window that opens where it was
told to. `saved_bounds` is `""` and `saved_field` is `0.0` unless all four are present *and* are
numbers, and the break above is what holds that in place.

Residual doubt, and the windowed half is larger than usual here.

  * **Nothing was run.** The whole check is a `#[test]` file plus the `check` tier. What is
    proven is the store and the parse; what is *not* is the two places a window is involved:
    `gpui::save_window_state` reading a live window's `bounds()`, and a window actually opening
    at the remembered position. Both are code that runs, neither has been observed to run. The
    owner of this machine has forbidden windows, which is why; see "Headless mode".
  * **A running window cannot be moved.** `Window::resize` exists and `Window::bounds` reads;
    there is **no public API anywhere in gpui 0.2.2 to set a window's position** — searched for
    `set_position`, `set_origin`, `move_window`, `set_window_position`, `setFrameOrigin` and
    `setFrameTopLeftPoint` across `window.rs`, `platform.rs` and `platform/mac/window.rs`, and
    the only hits for a window's geometry are the two getters and `resize`. So the row's
    "restore" is a restore **at open**, which is the only kind the toolkit has: a program that
    wants a running window to move cannot make it. Recorded in `## Unreachable` with the search.
  * The store is **last-writer-wins** and has no locking: two processes writing the same file
    lose one another's keys. It rewrites the whole file on every change, so a very large store
    would be slow, and comments or blank lines a person added by hand are not preserved.
  * `settings_set` answers `false` rather than raising an event when the file cannot be written;
    `save_window_state` raises `"~settings.bad|<why>"`, so the two halves report differently.
  * The path is the program's to choose and nothing checks that two programs do not choose the
    same one.
