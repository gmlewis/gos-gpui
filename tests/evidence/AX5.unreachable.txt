Fourteen fields and no icon among them. An application icon is a property of the running
application, not of a window, and gpui 0.2.2 has no API for the application either.

**Notifications** are worse than missing, because the word is there and means something
else. Every hit for it in the crate is the *entity* notification model:

    $ grep -rn "notification" ~/.cargo/registry/src/*/gpui-0.2.2/src | grep -v "///" | head -2
    .../src/app/test_context.rs:467:    pub fn notifications<T: 'static>(

`cx.observe`/`cx.notify` — internal pub/sub between views, unrelated to
`NSUserNotification`, `UNUserNotificationCenter` or the desktop notification daemon.
There is no OS notification call in the crate.

**The tray is the interesting one**, and it is why this row needed checking rather than
assuming. gpui 0.2.2 *does* have a macOS status item:

    $ grep -rn "NSStatusBar" ~/.cargo/registry/src/*/gpui-0.2.2/src
    .../src/platform/mac/status_item.rs:14:    appkit::{NSScreen, NSSquareStatusItemLength, NSStatusBar, NSStatusItem, NSView, NSWindow},
    .../src/platform/mac/status_item.rs:108:pub struct StatusItem(Rc<RefCell<StatusItemState>>);

`StatusItem` is `pub` — inside a module that is not reachable from outside the crate:

    $ grep -n "^mod platform" ~/.cargo/registry/src/*/gpui-0.2.2/src/gpui.rs
    31:mod platform;
    $ sed -n '89p' ~/.cargo/registry/src/*/gpui-0.2.2/src/gpui.rs
    pub use platform::*;
    $ grep -n "pub use mac\|pub mod mac" ~/.cargo/registry/src/*/gpui-0.2.2/src/platform.rs
    (no output)          # platform.rs:9 is `mod mac;`, private

So `pub use platform::*` re-exports what `platform.rs` itself declares — `WindowKind`,
`WindowOptions`, `ScreenCaptureSource`, and the rest — and nothing from the private
`mod mac` beneath it. `gpui::platform::mac::status_item::StatusItem` is not a path an
outside crate can write, and there is no re-export of it at the crate root.

The toolchain change that would close it: any of three, and each is upstream. A
`WindowOptions`-level icon (an `NSImage`/`HICON` path) for the app icon; a public
`StatusItem` constructor for the tray — it already exists and only needs to escape a
private module; and an OS notification call of any kind for notifications. Until then
the honest statement is the one in the row: **no API upstream**, not "not bound yet".

This is a route-D row in the register, and route D does not help here either: a Rust
widget lives inside the binding's own frame, and all three of these are outside the
window — the dock, the menu bar, and the system notification centre.
