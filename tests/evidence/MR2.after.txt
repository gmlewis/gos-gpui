and the keyboard layout.

**Three things are checked, and the strongest one is the program's own.**

  1. **The window left the window server's list.** That is the row's claim, and the
     program asserts it: before the call the server answers with a window number,
     after it, `0`.
  2. **The loop survived the call.** The frame posted after `hide()` arrived — 5.196s
     against the 5.181s the call was made at — which is the half of the row that says
     `hide()` does not stop the application.
  3. **What the window looked like.** `tests/evidence/MR2.before.png` sits beside this
     file and is the window *and nothing else*: title bar, the two lines of text, and
     "4.9923681250000005s". It was opened and confirmed.

**How that picture is taken, because it is the part worth reusing.** The probe asks
`CGWindowListCopyWindowInfo` for the windows of **its own pid**, through `osascript`'s
Objective-C bridge in JavaScript — no compiled helper, no title to match, and no
permission, since a window's pid, layer and number are not privileged (only its
*name* is, and this probe does not ask for one). It then runs
`screencapture -x -o -l <number>`. `-l` captures **that window's own pixels**: the
desktop is not in the picture and neither is anything stacked over the window, and
`-o` leaves the shadow out. So this evidence does not change when the person running
it switches workspace or opens a window on top — which the earlier version of this
probe's picture did, twice, in one afternoon.

**Two things were found by running it, and both changed the check.**

  * `kCGWindowListOptionOnScreenOnly` — the obvious query — is **wrong** here.
    `NSApp.hide:` orders an application's windows out *without* taking them out of
    the window server's list, so that query still named this window after `hide()`
    had visibly put it away. What changes is `kCGWindowIsOnscreen`: `true` before the
    call, **absent** after it. The probe asks for every window of this process and
    lets that flag choose.
  * **The answer has to be waited for, not read once.** One run in four had the hide
    land before the next frame and another had it not land yet — in that one
    `NSRunningApplication.isHidden` said `false` a millisecond after the call, and the
    window server still listed the window. That is the platform being asked before it
    had done anything, not a capability that failed. The probe now repeats the
    question for up to five seconds and reports the platform's answer. With that, the
    row is `tested` on all five tiers.

`refresh()` has no observable, and none is claimed: the probe calls it so the call is
exercised, and says so in the same line. `keyboard_layout()` reports "U.S." — the
platform's own answer. The old probe's red, and why it could never terminate without a
person, is in `MR2.before.txt`.
