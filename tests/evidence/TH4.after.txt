**The vocabulary.** `theme.<field>=<colour>`, where the field is one of `text`,
`selected_text`, `background`, `disabled`, `selected`, `border`, `separator`, `container`.
It is a different thing from `bg=` and belongs on the window's **root**: `bg=` colours one
element, while `theme.background=` changes what the platform answers for that name, and so
what `gpui::default_color` reports and what a framework default is chosen from.

```gossamer
ui::column("p=8 size=full theme.background=#111111 theme.text=#eeeeee")
```

**When it takes effect, and why that is not a bug.** A frame reads the colours at its
start and runs the view callback — which is what describes the root and carries the tokens
— after that, so the overrides a frame carries are applied to the *next* frame's colours.
`gpui::default_color("background")` therefore answers the new value one frame later. The
alternative would be to re-read the colours after the callback, which would mean every
element already built this frame had been styled against the old ones.

What is new:

  * `gpui-binding/src/style.rs` — `theme_overrides` parses the tokens in order, and
    `is_theme_field` is the closed list of eight. A token naming anything else is reported
    by the unknown-token machinery rather than skipped, so `theme.accent=` is visible as
    the mistake it is.
  * `gpui-binding/src/view.rs` — `THEME_OVERRIDES`, per window: the root's tokens recorded
    as the frame is built, applied to the colour set `begin_frame` caches.
  * `gpui-binding/src/lib.rs` — `gpui::theme_override(style)` returns the field names a
    style overrides, `"text,selected_text,…"`, in order.

**What the check does not cover, and the break that proves it.** The headless check is the
parse. The break that keeps the parse and removes the *application* — the recorded
overrides never reaching the frame's colours — leaves it green (86 passed, 0 failed). So
whether the window draws with the overridden colours, and whether `default_color` answers
them on the following frame, are unverified here; the second would be a two-frame GUI
probe and the first needs pixels this machine cannot capture. Both are in the row's
residual doubt.
