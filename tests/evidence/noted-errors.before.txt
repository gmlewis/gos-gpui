noted_errors — the red, and a second red that is not about the channel at all
Tier: gos run --main-thread (interpreter), and one deliberate break in the binding.

WHAT THIS PROBE IS. `tests/gui/noted_errors.gos` is not a register row. It is the
instrument the register's checks need: the binding reports its problems by drawing
a banner inside the window and printing nothing, and a window that draws an empty
box says nothing on stdout, on stderr, or in its exit status.

THE HISTORICAL RED, which is the one that mattered and is already in this
directory. Through rounds 81 and 82 `examples/02_data_table.gos` drew its rows
**empty** — 42 tinted bars with no text — and passed every silence check the suites
had, because an empty box is silent. `EX02_ROWS.before.png` is that window.
Nothing in this project could see it. That is the hole the channel closes, and it
is why `scripts/probes.sh` and `scripts/regress.sh` now fail a run that only notes an
error.

THE TRANSCRIBED RED. `gos check` does not resolve binding names (round 82 proved
it: a call to `gpui::this_name_absolutely_does_not_exist` answers `check: ok`), so
a red for the channel's absence cannot be captured on the check tier. It is
captured on the `run` tier instead, by breaking the channel on purpose — the
reader was made to answer with an empty list:

    pub fn noted_errors() -> Vec<String> {
        // TEMPORARY BREAK
        if true { return Vec::new(); }
        ...
    }

    $ DSH_ALLOW_WINDOWS=1 GOSSAMER_NOTED_ERRORS=1 \
        ./scripts/run-once.sh tests/gui/noted_errors.gos 20
    window-guard: windows ALLOWED (DSH_ALLOW_WINDOWS=1)
    NOTED before anything went wrong: 0 message(s)
    gpui: unknown style tokens: notatoken=7
    gpui: noted: unknown style tokens: notatoken=7
    NOTED the program can read what the person would see: #[]
    FAIL noted_errors the binding noted nothing for a token it does not know — either the token is known, or the channel is broken

The break was reverted immediately and the probe then passed; the green is in
`noted-errors.after.txt`. Note what the red shows: stderr **did** carry
`gpui: noted: unknown style tokens: notatoken=7` while the program's own reader
answered `#[]`. The two halves of the channel are independent, and only one of
them was broken — which is exactly the distinction this file is for.

THE SECOND RED, AND IT IS THE ONE WORTH READING. The probe's first version reached
no verdict at all, and it looked like a broken channel rather than a broken probe:

    $ ./scripts/run-once.sh tests/gui/noted_errors.gos 25
    window-guard: windows ALLOWED (DSH_ALLOW_WINDOWS=1)
    DIAG frame 1 at now=0.000000167s
    NOTED before anything went wrong: 0 message(s)
    gpui: unknown style tokens: notatoken=7
    gpui: noted: unknown style tokens: notatoken=7
    DIAG frame 2 at now=0.056216875s
    (nothing for 20 seconds)
    === exit=124 ===

Two frames, then silence, then the timeout killed it. **gpui draws a frame when
something asks it to, and a still window asks for nothing** — the probe rendered a
static tree and never called `gpui::animate()`, so the loop delivered the open and
one frame after it and then went quiet, and the `f >= 3` verdict was unreachable
code. `tests/gui/mr2_hide.gos` had the same shape and worked only because its tree
animates.

So the probe was fixed, not the verdict: `gpui::animate()` now sits in the frame
body with a comment saying why. Had this not been run, the file would have carried
a timeout that reads as "the noted-error channel does not work" when the channel
was never asked.
