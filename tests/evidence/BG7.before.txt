BG7 — file I/O and threads from Gossamer as the escape hatch.

BEFORE THE WORK. The row's whole obstacle is that the question had never been asked:
*"`apps.md` records this as undetermined; the toolchain was never run for it"*. So this
before-transcript is that run — and it is a set of **compile errors**, which is what the
register asks a before-file to contain. What it does *not* contain is a defect in the
binding: this row is not about the binding. It is about what a program can reach when a
capability has no binding function and no Rust widget, and the answer was unknown.

**Attempt 1** — guessing at the two namespaces the Rust side of `gossamer-std` makes
obvious (`crates/gossamer-std/src/fs.rs`, `thread.rs`):

    $ cat tests/zz_std_probe.gos
    use std::fs
    use std::thread

    fn main() {
        let r = fs::write("/tmp/gos-bg7-probe.txt", "hello")
        let t = thread::spawn(|| { 7 })
        match thread::join(t) { Ok(v) => ..., Err(_) => ... }
    }

    $ env -u GOSSAMER_IN_RUNNER gos check tests/zz_std_probe.gos
    error[GR0001]: cannot find `thread::spawn` in this scope
    error[GR0001]: cannot find `thread::join` in this scope
    error[GT0001]: type mismatch: expected `Vec<u8>`, found `String`

Three different things at once, and each is a fact about the toolchain rather than about
this binding: **file writing exists** and takes bytes, **threads do not exist in the
language's scope at all**, and a string is not bytes.

**Attempt 2** — which of the names that exist on the Rust side are bound:

    $ gos check (a probe calling each candidate once), filtering the diagnostics
    cannot find `fs::current_dir` in this scope
    cannot find `fs::remove_all` in this scope

    (so `remove_dir_all`, `remove_dir`, `create_dir`, `create_dir_all`, `metadata`,
     `copy`, `rename`, `canonicalize`, `read_dir`, `read`, `read_to_string`, `write`,
     `exists` and `remove_file` *are* bound; `current_dir` and `remove_all` are not)

**Attempt 3** — the language's `Result` discipline, which is stricter than it looks:

    error[GT0007]: unused `Result` value - the `Err` variant may go unhandled
      = help: propagate the error with `?`, handle it with `match` / `if let`, or
              explicitly discard with `let _ = <expr>`

    error: 5 front-end error(s); refusing to execute

Every scratch probe used to find all of this was deleted immediately: `gos test tests`
runs every `*.gos` under `tests/`, so a file that does not compile does not belong in the
tree.

Not one line of `gpui-binding/` was needed, and none was written. The work this row
called for was finding out, and the artifact that turns "undetermined" into a fact is the
check in `BG7.after.txt`.
