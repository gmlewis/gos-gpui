MR1 — the `Window` accessor batch: which window the platform calls active.

AFTER THE WORK. **Two windows, no clicks, and the handle turned into a name this crate understands.**

    $ DSH_ALLOW_WINDOWS=1 ./scripts/run-once.sh tests/gui/mr1_active_window.gos 60
    MR1 asking which window is active; before the answer, active_window() is 0
    MR1 this is window 1, and the platform says window 2 is active
    OK MR1 the platform named one of this program's own windows as the active one, and the binding turned the
    handle into its own name

Three things are in that transcript. The answer was **0 before the question** — the reader says "nothing known"
rather than guessing. The platform named **window 2**, and this frame is running in window 1, so the walk found
a window that is *not* the one asking, which is the part that could most easily have been quietly wrong (a
binding that answered "the current window" would have said 1). And the handle the platform gave — an
`AnyWindowHandle` — became this crate's own name only by reading each open window's root view, which GPUI
refuses from inside a frame, which is why `find_active_window` runs from a deferred callback.

All the row's other names were already reachable: `is_maximized` and `is_fullscreen` are observed fields,
`gpui::mouse_position()` is the cursor, `gpui::focused()` the focused element, `gpui::keyboard_layout()` the
layout. The row's "*more* `window_field` names" was open-ended; it is now defined as the list its own obstacle
column gives, and that list is complete.

Residual doubt: **`active_window()` is `0` in two different situations** — before the first ask, and when the
platform names no window of ours because this application is not frontmost — and they are not distinguished, so
a `0` is evidence of nothing until the window is in front. The compiled tiers are unrun. Tiers: `check`, `run`.
