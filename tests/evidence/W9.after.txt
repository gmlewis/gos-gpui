W9 — a second (and third) concurrent top-level window, without re-entering
`run`.

AFTER THE WORK. Command, in this tree:

    TIER_TIMEOUT=25 ./scripts/tiers.sh tests/gui/w9_three_windows.gos

Output, identical on all five tiers (`check` prints `check: ok (1 items typed)`;

    OK W9 three windows: 1, 2 and 3, one run call, no re-entry

What the probe does: window 1's frame opens window 2; window 2's frame opens
window 3; window 3 reports its own id back into window 1's state namespace with
`gpui::set_int_in`. Window 1, at frame 8, requires that report to be 3 and its
own id to be 1, then quits. Three view callbacks, three ids, one `run`.

`W9.before.txt` records why the before-transcript for this row is the weaker
kind: the probe cannot run at all at HEAD, because `gpui::window_id` and
`gpui::set_int_in` do not exist there. The behavioural evidence for "two windows
that do not corrupt each other" is W3's and W7's.
